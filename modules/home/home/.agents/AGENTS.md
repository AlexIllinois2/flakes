# AGENTS.md
- 磨刀不误砍柴工: 定好合理约束, 省很多事后修补

## env
- PATH: ~/.local/bin, ~/.local/app
- js: bun, nvm
- py: python3, uv
- 国内源: 所有工具链下载依赖一律默认用国内源, 禁止有国内源的情况下直接使用官方源

## layout
- README.md, README.zh-CN.md: 双语文档, 也是doc和AGENTS入口, 须引导agents阅读AGENTS/AGENTS.md
- doc/: 文档
- AGENTS/: AGENTS.md, memories/, skills/等. agents的记忆必须存放一份到AGENTS/memories/
- src/: 源码
- conf/: 长期有效的配置文件
- db/: 类似数据库的必须的大型数据源文件
- script/: 构建脚本, 运行脚本等非源码的长期提效脚本
- tool/: 另外下载的sdk, 工具等(未解压)
- dist/: 当前构建产物
- release/: 人指定的版本释出(源码与产物, 各自打包)
- cache/: 解压的厂商文件, sdk, 工具; 捕获文件, 发音文件, 重打包的模型等
- tmp/: 临时文件, 一次性脚本, 一次性捕获/发音等. 记得及时清理
- .trash/: 一次性大量删除(禁止直接rm)的文件移动到这里, 之后如有需要, 从这里找回文件
- vendor/: 厂商文件(未解压的apk, 语音包等)
- model/: 解析出的模型
- 子目录合理拆分: 单层文件夹直接子文件超过30个就考虑分类；超过50个建议分；超过100个必须分。项目根目录超过10～15个就开始分。不要为了数量强行过度嵌套，一般目录层级控制在 3～5 层以内。务必保证每个文件夹职责清晰
- 禁止使用软/硬链接
- 禁止自动在项目外创建文件(夹), 如有需要, 向人说明并询问存放位置

## coding
- 接到需求先列详细, 合理, 且可行的计划再按计划执行
- 路径: 能写相对路径就不要写绝对路径
- 修改结束自动同步README.md, README.zh-CN.md后提交推送, 并用gh更新项目简介(中英双语)
- 阶段性目标结束自动整理新文件: 清理垃圾文件并归类留存文件; 同步目录结构说明到README.md中
- 快速开发/迭代中的项目的架构性调整禁止试图一次性**精密**修复所有可能的故障, 而是在开发迭代中碰到哪里修哪里

## test
- 没有明确声明本项目关乎性命的情况下, 禁止"紧了下螺丝就重新进行完整出厂测试"的荒唐行为: 禁止自动编写和运行测试用例/快闸/尺

## build/package
- 默认: release
- release: 默认用debug签名
- 版本号: 自动添加版本唯一标识如: v1.0.0-20260101-685f2b0f (ver-年月日-8位随机码)
- 命名: 如: {name}-{ver}-{platform}-release-debug_signed.apk
- 构建成本高(需要持续高负载运行超过2分钟)的项目禁止自动在本地构建和打包
- 后台任务 正常结束或异常退出时，必须用`notify-send` 发系统通知结果 （附关键输出/错误摘要）

## CI
- 自动为项目生成github ci: 推送版本号命名的tag自动构建打包所有平台release包(debug签名)并发布release
- doc: 声明软件包使用debug签名, 请从可信渠道下载安装
