## 修复 zsh 的 git 别名无限递归（FUNCNEST 报错）
- 现象：zsh 报 `git_init_process:4: maximum nested function level reached; increase FUNCNEST?`。
- 根因：`home/.local/shell/rc/git.sh` 定义 `alias git=git_init_process`，而函数体与别名值里又直接调用 `git`；home-manager 激活后留下 `git.sh.backup`，`home/.local/shell/zsh.zsh` 用 `find` 把目录里所有文件（含 `.backup`）都 source 一遍，导致同一配置被加载两次——第二次加载时 alias 已生效，函数体里的 `git` 被展开成 `git_init_process` 自身，形成递归。
- 修改：
  - `home/.local/shell/rc/git.sh`：函数体、别名值、`git_is_repo` 内部全部改用 `command git` 绕过 alias，并加注释说明。
  - `home/.local/shell/zsh.zsh`：两处 `find` 增加 `! -name '*.backup'`，避免重复 source。
- 验证：用 `zsh -f` 模拟重复 source 及按新 zsh.zsh 加载，`git status` 均正常（设置了 FUNCNEST=20）。
- 注意：改动位于 home-manager 源文件，需用户自行执行 `home-manager switch` 才会同步到 `~/.local/shell`；未擅自构建/切换。当前 shell 临时规避可执行 `unalias git`。
